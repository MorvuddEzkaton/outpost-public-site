## Виявлено

1. **P1 — дефект XML-джерела.** У sitemap після першої адреси траплявся буквальний текст `\\n` замість перенесення рядка. Виправлено в цьому PR. Оновлено `lastmod` тільки на сторінках, які дійсно змінені.
2. **P1 — відсутня навігація до резервної каси.** До цього PR функцію не було описано на головній, сторінці модулів і сторінці offline. Додано внутрішні переходи та змістовний розділ. Резервний запис чітко відокремлено від фіскального чека.
3. **P2 — потенційно застарілий snippet.** Пошуковий результат `/download` відображав старий текст v0.24.10, тоді як у поточному GitHub-коді є v0.24.42. Не міняти URL і файли інсталятора; перевірити в URL Inspection після доступу до Search Console.
4. **P2 — можливе перетинання намірів запитів.** `/avtomatyzatsiya-magazynu`, `/avtomatyzatsiya-rozdribnoi-torgivli`, `/programa-dlya-nevelykogo-magazynu` та `/programa-dlya-fop` потребують перевірки канібалізації за реальними `query × page` даними; не видаляти/не зливати сторінки без них.
5. **P3 — відносно довгі описи.** Деякі `description` мають 175–201 символ. Це не технічна заборона; оптимізувати за реальною видачею і CTR, а не механічно обрізати.
6. **P3 — нові можливості й документація.** Перевіряти свіжість текстів після наступних релізів, особливо статути ПРРО, інтеграцій, мобільної каси, інсталяторів.

## Здорові властивості

- Основні індексовані сторінки мають окремі `title`, по одному `H1`, `description`, canonical та Open Graph.
- На перевірених сторінках HTML-зображення мають `alt`; вбудовані JSON-LD блоки парсяться.
- `robots.txt` дозволяє публічне сканування, посилається на sitemap і виключає `/admin`. Захист приватних API визначається авторизацією, не robots.txt.
- `demo.html` має `noindex,nofollow`; `404.html` має `noindex, follow`; обидві відсутні у sitemap.
- Є захищений main та перевірки static/browser/security перед production-публікацією.

### План SEO-робіт (спершу перевірити результати PR #31)

1. **P1: чітка сегментація наміру** для трьох сторінок про автоматизацію: магазин в цілому / роздрібні продажі / закупівлі та склад. Уточнити H1, перші 200–300 слів, приклади робочих сценаріїв та текстові внутрішні посилання; не робити механічне дублювання контенту.
2. **P1: /avtomatyzatsiya-magazynu** має 369 показів, 0 кліків і позицію 67,69 — не очікувати кліків від однієї зміни snippet, поки сторінка на 6–7-й сторінці видачі.
3. **P1: /avtomatyzatsiya-zakupivel-i-skladu** має приріст 105→261 показів. Посилити під підтверджений запит `автоматизація закупівель і складу`, сценарії закупівель/постачальників, показати реальний інтерфейс.
4. **P2: /mini-t400** (5 кліків / 14 показів) і **/download** (2 / 62) — бережно зберігати релевантність, не міняти URL і не ламати конверсійний шлях.
5. **P2: мобільна верстка** важлива: половина кліків надходить із mobile (7/14). Окремо перевірити фактичний CWV; GSC через Windsor не надає Core Web Vitals або URL Inspection.
6. **P2: резервна каса** має точну цільову проблему (відключення електроенергії), спочатку перевірити індексацію доданих блоків і появу запитів про аварійну касу; нову окрему SEO-сторінку робити тільки за наявності потреби та підтвердженого публічного опису продукту.
7. **P3: Search Console URL Inspection** у прямому інтерфейсі, щоб підтвердити фактичну індексацію, причини виключення, а не вважати 26 submitted = 26 indexed.

**Обмеження інтерпретації:** дані Windsor відповідають вибраному URL-prefix ресурсу, не всім субдоменам і не всьому Google; деякі запити приховані через правила конфіденційності Google. Відсотки та позиції не доводять причинно-наслідкового зв'язку з переносом на публічний GitHub або з конкретним SEO-PR.
