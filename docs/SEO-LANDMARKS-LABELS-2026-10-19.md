# SEO / доступність OutPOSt — структура головної і переходи до цінників

Дата: 2026-10-19. Scope: виключно публічний HTML, sitemap, офлайн- та браузерні перевірки. **Ні Cloudflare конфігурації, ні D1, ні ліцензій, ні кабінету чи фіскальної логіки не змінено.**

## Передумови

- Google Search Console через Windsor.ai (URL-prefix `https://outpost.com.ua/`), фіксовані 28 днів **19.09–16.10.2026**: `/avtomatyzatsiya-magazynu` — 365 показів / 0 кліків / середня позиція 66,64; `/avtomatyzatsiya-zakupivel-i-skladu` — 273 / 0 / 64,51; `/avtomatyzatsiya-rozdribnoi-torgivli` — 99 / 0 / 48,01. `/tsinnyky-ta-etyketky` — 2 покази / 0 кліків / позиція 32.
- SEO-хвилі для трьох сторінок автоматизації опубліковано лише **19.10.2026**, тому ці числа **не оцінюють** їхній результат. Повторно змінювати контент цих сторінок для ключових фраз зарано.
- Статичний аудит виявив у `site/index.html` порядок **`<footer>…</footer><section class="seo-depth-section">…</section></main>`**. Глобальний footer потрапляв у головний landmark `main`; додаткові запитання стояли в DOM після підвалу. Це семантичний дефект, а не підтверджена причина низьких позицій.
- Цільова сторінка цінників має три реальні скриншоти, власний редактор і важливі застереження щодо фізичного друку, але зі сторінки `/`, обліку товарів і спеціалізованої закупівельної сторінки до неї немає цільових посилань.

## Виправлення

1. Переміщено наявний блок додаткових FAQ **перед** глобальним підвалом і всередину `main`; `</main>` тепер перед `<footer class="footer">`. FAQ-текст та відповіді збережено, лише прибрано історичне формулювання «на попередній головній».
2. У блоці «Ще сценарії» головної додано посилання **«Цінники та етикетки»** на чинний `/tsinnyky-ta-etyketky`.
3. Додано такий самий контекстуальний перехід до вже існуючих «Пов’язаних сторінок» на сторінках обліку товарів та закупівель і складу. Без нових маркетингових обіцянок.
4. `lastmod` сторінки `/oblik-tovariv-u-magazyni` піднято з 16.10 до **19.10.2026**; дата інших двох змінених сторінок у sitemap вже **19.10**, тому не змінювалась.
5. Після правильного закриття `main` SEO-guard виявив три сторінки, для яких попередньо помилково враховувалися footer-посилання: бухгалтерія ФОП, бухгалтерський облік магазину та CheckBox. Додано **по одному** тематичному переходу в `main` зі сторінок `/programa-dlya-fop`, `/oblik-tovariv-u-magazyni` та `/prro`, не послаблюючи мінімум 3 контекстних inlink; `lastmod` `/prro` = 19.10.2026.
6. Розширено `scripts/verify_public_site.py` fail-closed перевіркою порядку семантичних блоків і посилань; додано браузерний тест `homepage landmark order and label-workflow links stay accessible`. Увесь інший CI залишається обов'язковим.

## Обмеження і приймання

- Дотримано одного H1, незмінні canonical, метаописи, JSON-LD та цільові URL; збережено всі 26 записів sitemap.
- Немає підстав називати зміну `/tsinnyky-ta-etyketky` «зростанням SEO»: знадобиться нова статистика через щонайменше 14–28 днів.
- За успішного CI дозволено merge → автоматичну публікацію лише protected `main` → незалежну live-перевірку. Резервна точка `backup/pre-seo-landmarks-20261019`, SHA `408a3bf0fd4e9f834bf120c0e53bd8a10184bb22`.
- Перевірка публічного entry кабінету в CI **не дорівнює** входу користувача і наскрізному прийманню синхронізації продажів; ці контури не торкаємося.
