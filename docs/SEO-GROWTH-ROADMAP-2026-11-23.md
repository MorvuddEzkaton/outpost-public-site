# OutPOSt — SEO Growth Roadmap (23.11.2026 → 14.02.2027)

**Мета:** отримати більше релевантних відвідувачів із Google, які шукають Windows-програму для невеликого магазину, каси, закупівель та складу, і збільшити частку таких відвідувачів, що переходять до демо/завантаження. Ціль — корисність для власника магазину, а не кількість проіндексованих SEO-сторінок.

**Робочий протокол:** кожен етап виконується окремими перевіреними PR; ніяких незатверджених правок production, фонових публікацій за розкладом чи автоматичних публікацій на сторонніх майданчиках. Етапи виконуються під час активних робочих сесій за дорученням власника. Історичні дані й проміжні результати зберігаються в GitHub; власник може продовжити виконання в новому чаті за цим документом.

## 2. План на 12 тижнів

### Етап A — 23.11–06.12.2026 (тижні 1–2) · P0/P1

- [x] Зафіксувати вихідний стан GSC, sitemap, технічних обмежень у `SEO-GSC-AUDIT-2026-11-23.md` (PR #120).
- [x] Гард для `/downloads/*` з `X-Robots-Tag: noindex`; точна межа в CI; PR #120, продакшн перевірено.
- [ ] Сторінка закупівель: **приклад для власника** з реальними складськими розвилками (план ≠ фактичне приймання, що робити з недопоставкою та з кількома складами), а не дубль опису модулів.
- [ ] Невеликий магазин: **перший робочий сценарій** (товари/штрихкоди, фізична звірка залишків, каса, резервна копія, пробний доступ) без обіцянки імпорту «за хвилину».
- [ ] Контекстні внутрішні посилання між двома сценаріями та загальною автоматизацією — тільки там, де це допомагає людині.
- [ ] Кожен PR: 6/6 CI → squash із `(#PR)` → protected production → незалежний live verifier. Не обходити guard.
- [ ] Отримати **URL Inspection** для ключових URL (потрібен окремий доступ до API/веб-перегляду власника); зафіксувати indexed/not indexed, Google canonical, last crawl, а не вгадувати.

- [ ] Звірити реальні скріншоти **саме актуальної** версії та демонстраційних даних; першими: аналітика (Огляд, Товари, Категорії, ABC, Склад) і робочі сценарії списання; вихідні завдання #52.

- [ ] Якщо скріншоти не підтверджені: **не** публікувати їх під виглядом реального UI; натомість залишити поточні перевірені зображення.
- [ ] Покращити доступність, підписи, alt, вагу WebP; ніяких випадкових декоративних картинок.
- [ ] Скласти короткий тест UX: на desktop/mobile за 30 секунд знаходяться демо, умови Lite vs Full, актуальна версія, інформація про фіскалізацію.

### Етап C — 21.12.2026–17.01.2027 (тижні 5–8) · P1/P2

- [ ] На основі Search Console визначити 2–4 реальні запити з попитом і недостатньою відповіддю на сайті. Спершу розширити наявні сторінки. Нові статті лише за **самостійною користю**, унікальним змістом, внутрішніми посиланнями й відповідальним актуалізатором.
- [ ] Кандидати матеріалів (після перевірки актуальних запитів): перехід з Excel на POS; запуск обліку з фізичною звіркою; питання до програми перед придбанням; закупівлі та недопоставка.
- [ ] Сформувати список 10–15 тематично релевантних українських каталогів/видань/спільнот, перевіривши правила, аудиторію та відсутність платного спаму.
- [ ] Підготувати чесний опис продукту, 3–5 перевірених фото і матеріал для редакцій, **без** вигаданих відгуків, нагород чи кількості клієнтів.
- [ ] Публікації за межами нашого сайту, листи редакціям та домовленості — лише за окремим дозволом власника. Платні посилання без прозорого рекламного маркування не купувати.

### Етап D — 18.01–14.02.2027 (тижні 9–12) · оцінка результату

- [ ] Аналіз кожні **14 днів під час активної робочої сесії**: settled data від GSC; порівняння з рівним попереднім періодом, з фіксацією дат, джерел, фільтрів.
- [ ] Оцінити по кожній цільовій URL: impressions/clicks/CTR/position, зміни точних `page+query` пар, число **релевантних небрендових** кліків (з поясненням прихованих запитів Google).
- [ ] За наявності достовірних подій виміряти завантаження/demos з органіки; **не** заявляти конверсії з лічильника скачувань без атрибуції.
- [ ] Відмовитися від змін, що не дають покращення досвіду/пошукового наміру; перевірити SERP, чи не змінився намір, з яким ранжується URL.
- [ ] Наступний квартальний план — лише після зіставлення KPI, а не просто за календарем.

## 3. Контрольні показники

- **North Star:** органічні кліки за релевантними *небрендовими* запитами на цільові посадкові сторінки; не рахувати не повністю доступні query-дані як повний трафік.
- **Проміжні:** точний запит «автоматизація закупівель і складу» (поточна позиція 24,5; амбіційна ціль ТОП-10, без гарантії); кліки на його цільову URL, кількість запитів на позиціях 4–20, стабільна індексація.
- **Якість та безпека:** 6/6 PR CI, успішні protected publisher і live verifier, відсутність змін до checkout/download hashes/фіскального/кабінету, жодних 404 по нових внутрішніх посиланнях.
- **Потенційна конверсія:** демо/завантаження — окреме завдання після аудиту реальних метрик, без довільної установки сторонніх трекерів або порушення приватності.
- Не ставити фіктивну ціль «у 10 разів більше показів»: покази можуть зростати через нерелевантні запити на низьких позиціях.

## 5. Заборонені ризики

- Не зачіпати `cabinet.outpost.com.ua`, Worker/D1, дані покупців, токени, реальну базу каси, зв'язок ПРРО/CheckBox/MINI, програмні оновлення та інсталятори в SEO-PR.
- Не змінювати значення SHA, URL пакетів, ліцензійні умови й тарифи без перевіреної предметної причини.
- Не створювати масових URL, doorway pages, шкідливих редиректів, backlink farm, штучних відгуків.
- Не називати неофіційні сертифікати, нагороди, аудиторію або ROI фактами.
- Не публікувати фото зі справжніми даними магазинів, клієнтів, КЕП або банків.
