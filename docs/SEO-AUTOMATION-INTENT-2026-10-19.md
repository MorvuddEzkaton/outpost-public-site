# SEO-хвиля №2: розділення пошукових намірів — 2026-10-19

## Мета

Підвищити релевантність трьох сторінок автоматизації, які набирають покази, але не дають переходів. Це **зміни текстів**, а не перенесення URL, оновлення продукту чи фіскального API.

## Підтверджений baseline (Search Console через Windsor.ai)

Властивість `https://outpost.com.ua/`, 2026-09-18 — 2026-10-15, агрегація за URL:

| URL | Покази | Кліки | Середня позиція | Завдання сторінки |
| --- | ---: | ---: | ---: | --- |
| `/avtomatyzatsiya-magazynu` | 369 | 0 | 67.69 | Комплексна автоматизація магазину: каса + товарний облік + закупівлі + склад |
| `/avtomatyzatsiya-zakupivel-i-skladu` | 261 | 0 | 65.16 | Поповнення, замовлення постачальникам, приймання й переміщення |
| `/avtomatyzatsiya-rozdribnoi-torgivli` | 99 | 0 | 48.01 | Робота продавця й покупця: чек, повернення, лояльність, клієнти |

Запит `автоматизація магазину`: 33 покази / поз. 26.85; `автоматизація закупівель і складу`: 75 показів / поз. 33.41 за останні 28 днів.

## Зміни в цьому PR

- Уточнено три `title`, метаописи, `og:title` / `og:description` та відповідні `WebPage` JSON-LD; canonical URL збережено.
- Перші абзаци на всіх трьох сторінках тепер чітко називають їхню роль.
- На сторінці **автоматизації магазину** додано конкретні приклади каси, обліку товарів та закупівель із цільовими внутрішніми посиланнями.
- На сторінці **закупівель і складу** описаний керований процес: розрахунок поповнення → замовлення → часткове приймання.
- На сторінці **роздрібної торгівлі** додано сценарії касира, покупця та власника.
- `lastmod` змінено тільки для трьох реально змінених URL (2026-10-19).
- Збережені поточні H1, знімки реального інтерфейсу, навігація, кнопки завантаження, ціни й усі наявні можливості.

## Чого НЕ робили

- Не додавали штучних SEO-ключів, непідтверджених функцій, прихованого тексту чи FAQPage rich results.
- Не створювали дубльованих сторінок і не робили редиректів, канонікалізації між різними продуктами або змін контенту резервної каси (це окремий PR #31).
- Не змінювали кабінет, Workers, D1, ліцензії, ПРРО, MINI-T400ME, каталог інсталяторів та GitHub deployment configuration.
- Не робили production deploy і не приписували цим змінам зростання позицій до індексації Google.

## Приймання перед merge

1. Усі обов'язкові GitHub Actions зелені, включно з accessibility/keyboard/browser regressions.
2. На кожній сторінці один H1, одна канонічна адреса, коректні `title`, `description`, JSON-LD та внутрішні переходи.
3. Sitemap зберігає всі 26 наявних URL, зміна `lastmod` стосується тільки трьох сторінок.
4. Перевірити мобільне компонування нових секцій та клікабельність внутрішніх посилань у браузері перед production.

## Вимірювання ефекту

Порівняти результати по кожній цільовій сторінці через 28 і 56 днів **після фактичної публікації та індексації**, використовуючи однакові фільтри країни/пристрою та дату. Моніторити покази, кліки, CTR, позиції за точними запитами, зміну ключових URL у пошуку. Врахувати низький абсолютний обсяг і природні зміни попиту. Збільшення показів без кліків не вважати достатнім ефектом.
