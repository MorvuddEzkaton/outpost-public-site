## Джерела та обмеження

- Фактичні дані Google Search Console з підключеного **Windsor.ai**, конектор `searchconsole`, акаунт `https://outpost.com.ua/`. Дата отримання: **23.11.2026**; останній день основного інтервалу: **20.11.2026**.
- Безплатний тариф Windsor.ai надає лише останні 30 днів історії; GSC Wizard повертає `subscription_required`. Тому немає повної сумісної 28/56-денної бази до змін 19.10.2026. Не приписувати покращення позицій конкретному PR без належного порівняння.
- Windsor.ai не надає у цьому підключенні Google URL Inspection API. `sitemap.xml` і наявність показів **не дорівнюють доказу індексації всіх URL**. Висновки стосуються Search Analytics, а не статусу URL Inspection.
- Агрегати `date`, `page`, `query` та `page+query` різняться за покриттям і способом агрегації. **Не складати рядки різних вимірів як незалежні покази/кліки.** Для загальних денних підсумків використовувати лише розріз `date`.

## Sitemap і технічні висновки

- Google Search Console бачить `https://outpost.com.ua/sitemap.xml`: **27 submitted URL, 0 errors, 0 warnings**; останнє завантаження **19.11.2026**; подано **09.09.2026**. Це не кількість проіндексованих URL.
- На всіх пріоритетних сторінках у джерелі сайту є унікальні `<title>`, головний заголовок `<h1>` і змістовні описи; головні сторінки пов'язані внутрішніми посиланнями. Немає підстав змінювати адреси, редиректи або канонікали масово.
- Google Search Analytics окремо показав **5 показів** технічного `/downloads/OutPOSt-Lite-Setup-v1.1.0.sha256.txt`. Цей контрольний файл не є цільовою посадковою сторінкою. Безпечна вузька дія: через Cloudflare Pages `_headers` додати `X-Robots-Tag: noindex` лише для `/downloads/*` (історичні інсталятори, контрольні суми), **не змінюючи вміст файлів або посилання**. Не ставити `robots.txt Disallow` на цей маршрут: для виявлення `noindex` бот повинен мати змогу прочитати заголовок.
- Статус фактичної індексації кожного URL, Google-selected canonical, мобільні CWV і наслідки правки `noindex` потребують окремої повторної перевірки; без даних не робити заяв про успіх.

## Пріоритети наступних дій

1. Після індексації свіжого релізу **0.26.2** дивитися небрендові `page+query` метрики на `/avtomatyzatsiya-magazynu`, `/avtomatyzatsiya-zakupivel-i-skladu` та `/avtomatyzatsiya-rozdribnoi-torgivli`; змінювати матеріал лише за підтвердженим інформаційним дефіцитом, без keyword stuffing.
2. Покращити демонстрацію функцій лише **реальними** знімками нової версії, без даних покупців/ключів/магазинних фінансів — issues #52 і #55. Фото саме по собі не є гарантією росту позицій.
3. Перевірити URL Inspection/індексацію Google для `/`, `/download`, `/features`, `/modules`, `/offline-programa-dlya-magazynu`, трьох сторінок автоматизації, а також `/prro`; потрібен окремий доступ до URL Inspection, якого конектор Windsor не надає.
4. Повторити порівняння після щонайменше двох повних тижнів від публікації 23.11.2026; інтервали та джерела залишати явними. Якщо буде доступна довша історія, окремо виконати перед/після 19.10.2026 із коректним 28/56-денним вікном.
5. Без узгодженого технічного обґрунтування **не** робити масових змін slug, canonical, sitemap пріоритетів, robots.txt чи редиректів. Працювати тільки через PR із 6/6 CI, protected publish, exact SHA та independent live verification.

## Безпека змін цього PR

Технічне SEO-правило діє тільки на **публічні статичні файли** `/downloads/*` і не змінює HTTP status, байти завантажень, SHA, кешування, права доступу, Windows-інсталятори, ПРРО, кабінет директора, синхронізацію, Cloudflare Workers/D1 чи DNS. Передавати дані в production лише захищеним publisher.
