# OutPOSt — перша хвиля мобільної продуктивності, 2026-10-19

## Контекст

Після перевірки Google Search Console: 7 із 14 кліків (18.09—15.10.2026) отримано зі смартфонів. Це **пошукові кліки**, а не реальні Core Web Vitals.

Цей пакет **не** містить фактичних замірів PageSpeed Insights / CrUX для outpost.com.ua: результатів для цієї адреси через доступні інтерфейси не отримано. Не приписувати неперевірені значення LCP, INP, CLS, FCP або Lighthouse Score.

## Виявлені проблеми у вихідному коді

1. На головній сторінці панорама `hero-approved-panorama-v1.webp` (у GitHub ~160 КіБ) була стандартним HTML-`<img>` з `fetchpriority=high`, хоча CSS приховував її при ширині <= 700px. Звичайне `display:none` не гарантує, що браузер не завантажить уже виявлене HTML-зображення. Це ризик зайвих завантажень на мобільних.
2. На сторінці `/mini-t400` головне фото `mini-t400me-cutout.webp` (~56 КіБ) розташоване в першому екрані, але мало `loading=lazy` і без `fetchpriority`. Це могло відкласти завантаження помітного елемента в hero.
3. Інші сторінки мають скриншоти і CSS, але без незалежних мобільних вимірів не можна робити ширші висновки про LCP чи зайнятість main thread.

## Точкові зміни

- `site/index.html`: hero-панорама тепер декоративний `<div aria-hidden="true">`, а preload PNG/WebP заданий **лише для desktop** через `media="(min-width: 701px)"`.
- `site/assets/home-hero-desktop-v1.css`: невеликий окремий desktop-only stylesheet задає фонове зображення без правок глобального `site.css`. Геометрія, overlay, обмеження ширини та мобільний дизайн збережені.
- `site/mini-t400.html`: hero `img` використовує `loading=eager`, `fetchpriority=high`, збережені width, height, alt, decoding.
- `scripts/browser_ui.spec.mjs`: додані регресії для відсутності запиту панорами на вузькому viewport, наявності зображення на широкому viewport, видимості й високого пріоритету для MINI-T400.

## Безпека

- Окрема гілка від `main` `ae9d9a60a184e7620a78d26c7db90541a51cd623`. `main`, production, Cloudflare, кабінет, ліцензії, ПРРО/РРО, інсталятори й статистика не змінені.
- Не змінено наявні ресурси зображень, їхні bytes, API, маршрути або SEO-контент. Додано лише маленький CSS для desktop. Оновлено `lastmod` у sitemap для головної й MINI-T400 відповідно до захисних перевірок GitHub. Не впроваджено глобальний cache policy: версійні скриншоти можуть оновлюватися за тими самими шляхами.

## Перед злиттям

1. Усі шість обов'язкових GitHub CI guards мають бути зеленими.
2. Перевірити, що `/assets/hero-approved-panorama-v1.webp` **не завантажується** при ширині 390px, але **завантажується й відображається** при 1440px; немає зсуву й горизонтального переповнення.
3. Перевірити мобільне та desktop фото MINI-T400ME, щоб воно не виходило за екран.
4. Перевірити ліміт першосторонніх ресурсів CI; глобальний `site.css` не змінений.
5. Після **фактичного** схвалення й production deployment зробити по 3 повтори PageSpeed Insights mobile+desktop, зафіксувати медіани та CrUX за наявності реальних вимірів. Не плутати Lighthouse lab та Google CrUX field metrics.
