## Пакет A: OutPOSt Desktop — поточна версія

Під час зйомки записати конкретну версію в UI/пакеті та тему Modern/Classic. Джерело — **реальна Windows збірка** з **окремою синтетичною демобазою**; не брати робочу базу магазину, не копіювати ПІБ, адреси, телефони, ключі, токени чи справжні ціни/обороти.

| ID | Модуль / потрібний стан | Приймання |
|---|---|---|
| A1 | Розширена аналітика → **Огляд** | Видимий період, підсумки, порівняння; дані реалістичні, але синтетичні |
| A2 | Розширена аналітика → **Товари** | Колонки, фільтр/сортування та дані з демобази |
| A3 | Розширена аналітика → **Категорії** | Зрозумілі назви/розподіл |
| A4 | Розширена аналітика → **ABC** | Видимий поділ A/B/C, умови/пояснення в UI, де присутні |
| A5 | Розширена аналітика → **Склад** | Залишки/ризики та назви складів із демоданими |
| A6 | Кабінет директора / мережевий read-only | Тільки дозволені агрегати, статус підключення; без ліцензійного ключа, IP чи секретів |
| A7 | Чернетка списання перед збереженням | Товари, кількості, статус; жодних реальних партій магазину |
| A8 | Повернення до збереженої чернетки | Партії збереглися; кадр підтверджує, що можна продовжити |
| A9 | Проведення / контрольована помилка | Видимий фінальний статус; не фальсифікувати повідомлення |

**Якщо якась вкладка чи функція відсутня в цій збірці:** позначити `NOT AVAILABLE` і не створювати інсценованого скріншота. Потрібна саме перевірка дійсно наявного UI.

## Обов'язкові правила зйомки

1. Працювати на Windows з **релізною збіркою**; записати версію (з вікна Про програму/артефакту збірки), дату, тему та назву вкладки. Знімки потрібних екранів робити як PNG без обрізання важливих станів.
2. Демобаза з нереальними товарами, замовленнями, клієнтами, реквізитами й оборотами. Не фотографувати реальну торгову точку.
3. Показувати реальну назву вкладки, панель фільтрів і приклади записів; достатня читабельність на 100% зумі; вікно бажано не менше ~1280 px шириною, якщо UI підтримує таку ширину.
4. **Звірити кожен кадр**: немає суцільного білого полотна, запитів на пароль, помилкових старих повідомлень, персональних чи фінансових секретів, штучно перемальованих елементів; відповідність поточному продукту.
5. Додати до вихідного пакета реєстр `ID / файл / версія / вкладка / синтетичні дані / SHA-256 / QA PASS|FAIL`. Не публікувати поки хоча б одне фото не пройшло QA.
6. Лише після QA оптимізувати до WebP з коректними `width`, `height`, `loading=lazy`, українським `alt`; зберегти чіткість тексту. Публікувати під новим versioned assets-підкаталогом.
7. Перед сайт-PR підтвердити, що **наявний відео/фото-тур не дублюється**. Не переписувати опис функціональності без підтвердження зі збіркою.
8. Сайтовий PR: first-party resource guard, image decoding/blank-image guard, public asset budget, browser accessibility/responsive, 6/6 required checks, protected publish, independent live verify.

## Як діяти без готового пакета

- Залишити сайт з наявними перевіреними зображеннями, поки Windows-зйомка не завершена.
- Відстежувати окремо статус кожного ID, не об'єднувати B1–B6 у «готово» на підставі одного кадру.
- Підготовка цього документу **не** означає, що скріншоти створено, прийнято чи вже опубліковано.
